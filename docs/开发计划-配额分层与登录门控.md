> 日期：2026-08-08 | 决策：智囊团（老周+小龙）
> Pre-Flight：🔴 全流程（有替换 + 12+ 文件 + 涉及认证/持久化/配额）


## 一、最终决策

| 决策 | 结论 |
|------|------|
| 未登录 | 插件显示登录按钮，不可分析 |
| 注册 | 送 `SIGNUP_BONUS_QUOTA`（默认 10 次） |
| 免费 tier `free` | 初始 10 次 + 每日补充 `DAILY_FREE_QUOTA`（默认 3），懒重置 |
| 付费 tier `paid` | 每日补充 `DAILY_PAID_QUOTA`（默认 20），懒重置 |
| 付费方式 | MVP 阶段手动收钱 → 手动改 DB `tier='paid'`；日后接 Stripe |
| 缓存命中 | 不扣 quota |
| 每日补充方式 | 懒重置——每次读 quota 时发现 `last_reset_date` ≠ 今天 → 按 tier 补充每日配额 → 更新日期 |
| 盈利模型 | **不靠分析赚钱，靠验货抽佣。** 分析是漏斗入口 |


## 二、完整流程

```
用户打开 1688 商品页 → 点插件图标
│
├─ 未登录
│     └─ 显示 [🔐 Sign in with Google] 按钮
│
└─ 已登录
      ├─ 显示商品标题（从当前 tab 抓取）
      ├─ 显示 [🔍 开始分析] 按钮 + "今日剩余 N 次"
      │
      └─ 用户点击 [开始分析]
            │
            ▼
      POST /api/analyze
            │
            ├─ ① JWT 校验（中间件 → request.state.user_id）
            ├─ ② 提取 offer_id
            ├─ ③ 全局限流 rate_limiter.check()（30次/分钟，rate_limiter.py 不动）
            ├─ ④ 查缓存 → 命中 → 返回（不扣 quota）
            └─ ⑤ 未命中
                  ├─ user_repo.get_quota_info(user_id) 读 quota + tier + last_reset_date
                  ├─ 懒重置：last_reset_date ≠ 今天 → quota += 每日补充量（上限=每日补充量）
                  ├─ quota ≤ 0 → 拒绝（QUOTA_EXHAUSTED）
                  └─ quota > 0 → user_repo.decrement_quota(user_id) → 启后台任务
                        │
                        ▼
                  后台 _run()
                        ├─ 二次查缓存（防并发）
                        ├─ Apify 抓取（apify_adapter.py）
                        ├─ map_raw() 清洗（data/mapper.py）
                        ├─ judge_all() 判词（verdict_engine.py）
                        ├─ cache.set() 写内存缓存
                        └─ build_result_with_display()（ai_verdict_svc.py）
                              ├─ zh → build_display() 模板（display/builder.py，始终调用）
                              └─ 非zh → build_with_ai()：先 build_display() → 再 Qwen 翻译+AI判词
                                    │
                                    ▼
                  前端轮询 GET /api/analyze/{task_id}
                        └─ status=done → render() 渲染 5 块报告
```

```
quota 字段规则（users 表，单字段）：

┌──────────────┬─────────────────────────────────────┐
│ 注册         │ quota = SIGNUP_BONUS_QUOTA (10)    │
│              │ last_reset_date = 今天              │
│ 每次分析     │ quota -= 1（DB UPDATE 原子）        │
│ 缓存命中     │ 不扣                                │
│ 懒重置       │ 每次读 quota 时检查                 │
│              │ last_reset_date ≠ 今天              │
│              │ → 补地板，不削顶：                  │
│              │   if quota < 每日补充量：           │
│              │       quota = 每日补充量            │
│              │   else：                            │
│              │       不变（赠送次数跨天不丢）       │
│              │ → last_reset_date = 今天             │
│ Apify 失败   │ quota += 1（refund）                │
│ quota ≤ 0    │ 拒绝（QUOTA_EXHAUSTED）              │
└──────────────┴─────────────────────────────────────┘

tier → 每日地板（env 变量）：
  free → DAILY_FREE_QUOTA（默认 3）
  paid → DAILY_PAID_QUOTA（默认 20）

补地板规则：只补差、不削顶、不累加。
  if quota < 地板 → quota = 地板
  if quota ≥ 地板 → 不变
```

  Day 2    │ 懒重置    │ 7 ≥ 3 → 不变   │    7     │    7      │

  Day 3    │ 懒重置    │ 2 < 3 → 补到3  │    2     │    3      │

  Day 4    │ 懒重置    │ 1 < 3 → 补到3  │    1     │    3      │
           │ 没用      │ —             │    3     │    3      │

### 清单检查

**功能完整性：**
```
✅ 调了外部 API？       → Apify + Qwen，超时/降级不变
✅ 加了缓存？           → 缓存逻辑不动，命中不扣 quota → 路由里前置拦截
⚠️ 加了内部标记字段？   → users.quota + users.tier + users.last_reset_date，需 DB ALTER TABLE
✅ 加了新模块/文件？     → 无
```

**防御性编程：**
```
⚠️ 外部挂了怎么办？     → Apify 失败 → refund quota（DB increment），不再依赖内存 quota_refund
✅ 数据会泄漏吗？       → tier/quota/last_reset_date 不在前端响应体。GET /api/quota 只返回 {remaining, daily_limit, tier}
✅ 会无限增长吗？       → 懒重置 + 上限 = 每日补充量，quota 不会累积超过一天的量
✅ 并发安全吗？         → quota 扣减用 DB UPDATE quota = quota - 1 WHERE id = ? AND quota > 0，原子操作
```
