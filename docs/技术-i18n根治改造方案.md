## 一、病根（三类会反复出现的结构性缺口）

1. **中文原文当字典钥匙 / data_key / 透传字段**：glossary.json 有 **58 个含中文的键**（33 纯中文词如 `实力工厂`、20 `unit_个`、5 数字开头）。`_supplier.py` 把中文词写进 `data_key`，`builder.py` 又原样写回 display JSON → **非 zh display 里躺着中文**。`certType` / `factoryFlags` / `shippingLocation` / `specs` 是 mapper 纯透传、永不过翻译层。
2. **AI 判词英文中继双跳**：档位词 / 身份 / 认证 / 单位全部**强制 en 查表或硬编码英文**喂给 AI，ru/vi/th 拿到英文后**自己再翻一遍** → 每次可能翻出新词（Надёжная vs Проверенная）、语法漂（Светящийся подставки）。另有认证名中文旁路直接喂 AI。
3. **语言集合无单一真源 + 完整性无测试锁**：语言白名单散落 8+ 处行内元组（builder:76 / analyze_svc:150/288/331/430 / ai_verdict_svc:43/86 / auth:147）；glossary 5 语言结构、壳 lang key 对齐（**测试只锁 4 语言漏了 ru**）、msg_code ru、display 非 zh 无中文 **全无 pytest 锁**。加语言漏一处 = 静默中文 / 缺 key。

## 二、三层定位（哪里对、哪里错）

| 层 | 现状判定 | 根因 |
|---|---|---|
| 🖥️ ① 壳 | ✅ **本身是对的**（lang JSON 已是 key 写法） | 只缺：语言集合统一登记 + ru 进完整性测试 |
| 📖 ② 字典 | ❌ **底层错：中文当钥匙** | 中文 = 源语言文字，被当成结构 ID → 中文焊死、清不掉 |
| 🤖 ③ Qwen | ❌ **底层错：英文中继再翻一遍** | 抢了字典的活 + 双跳累积错译；认证名中文旁路漏网 |

> **一句话**：中文只允许活在字典/glossary 的"值"里，不许当"钥匙"；AI 只允许翻译一次，不许接力翻。

## 六、改动大小（实数）

- 代码有效改动 **~200-300 行**，一大半是「行内元组 → import LANGS」机械替换。
- 成本集中在两处：① glossary **58 键映射表**人工核对（错一个 = 该词全语言丢翻译，此表会分批过目再落）；② 批 C 判词措辞回归。
- 前端 / bot 渲染层**零结构改动**（display JSON 契约不变）。

| 批 | 量级 | 风险 |
|---|---|---|
| A 护栏 | ~半天 | 零（纯搬常量 + 加测试） |
| B 字典 58 键 | ~1天 | 高（数据层手术，映射表人工核对） |
| C AI 单跳 | ~1天 | 中（判词措辞会变，需回归，可单批回滚） |

## 七、风险与注意事项

1. B 批是**数据层手术不是加功能**：58 键映射表逐个核；unit 改名前先盘 mapper 原始单位全集，映射表带"未知兜底 ASCII 直出"。
2. **别名表是临时过渡**：老中文键只读兼容 1 个版本，测试锁"不残留"后删。
3. 批 C 后 ru/vi/th 判词**可能变短/变措辞** → 用现成真实 offer 比对新旧，不达标单独回滚批 C。
4. **每批独立 commit、独立 revert**，出问题只回滚出事那批，不牵一发动全身。
5. 改文档（checklist / v2落地计划 §六 / README）**需另批授权**，不随代码批次。
6. glossary 中文原文如有改动，须同步四语言（铁律九）：不同步 → 删旧值，前端降级显示中文。
