# 分析即落库方案

> 2026-08-10 | 老黄 | 替换手动保存 → 全自动 DB 持久化
>
> 最终结论：去缓存、去 result_json、分析时存什么语言就是什么语言、回看直接读 display_i18n

---

## 一、缓存

**不留。`analysis_cache` 数据缓存代码注释掉，`_pending` 请求合并保留。**

理由：内存缓存只省了 5ms DB 查询 + 10ms mapper 重跑。Apify 本身 10-90 秒，省这 15ms 毫无意义。DB raw_json 永久有效，比 30h TTL 缓存更强。

```
分析启动
  → DB 查 raw_json → 有 → 跳过 Apify（永久，不像缓存 30h 过期）
  → DB 查 raw_json → 无 → 调 Apify
```

---

## 二、存储原则

**不存 result_json。raw_json 是唯一数据源，mapper 是纯函数，随时可重跑。**

```
analysis 表
├── raw_json       TEXT  ← Apify 原始（新增，唯一数据源，不可丢）
├── display_i18n   TEXT  ← 翻译后 display {en: {...}, vi: {...}}
├── favorited      TINYINT ← 收藏状态 0/1（新增）
├── title, image_url, price_min, price_max ← 历史列表
└── result_json    ← 旧列保留不写，一个月后 DROP
```

---

## 三、完整流程

### 3.1 第一次分析

```
用户选英文 → 分析
  → Apify 抓取 → raw_json
  → mapper → judge → build_display + Qwen 翻译英文
  → DB UPSERT: raw_json + display_i18n={"en": 英文版 display}
  → 前端渲染英文报告
```

### 3.2 回看历史（同语言）

```
点历史 → GET /api/report/{offer_id}?lang=en
  → DB 读 display_i18n → 取 "en"
  → ✅ 直接返回。零计算，零 AI 调用。
```

### 3.3 切语言

```
英文切越南文 → GET /api/report/{offer_id}?lang=vi
  → DB 读 display_i18n → 没有 "vi"
  → 读 raw_json → mapper → judge → build_display + Qwen 翻译越南文
  → display_i18n 更新为 {"en": 英文, "vi": 越南文}
  → 下次切回英文也不用重跑
```

### 3.4 再次分析同一商品（防重复 Apify）

```
用户再次分析同一 offer_id
  → DB 查 raw_json → ✅ 有
  → 直接用 raw_json 跑 mapper → judge → display → 翻译
  → UPSERT 更新 display_i18n（追加当前语言）
  → 不调 Apify
```

## 四、每次分析 DB 操作

| 场景 | DB 操作 | 次数 |
|------|---------|:--:|
| 分析（DB 已有 raw_json） | SELECT + UPSERT | 2 |
| 分析（DB 没有，需 Apify） | COUNT + UPSERT（+ 超限时 DELETE） | 2-3 |
| 历史列表 | SELECT (title/image/price) | 1 |
| 回看（display_i18n 命中） | SELECT (display_i18n) | 1 |
| 回看（display_i18n 未命中） | SELECT + UPDATE display_i18n | 2 |
| 收藏切换 | UPDATE favorited | 1 |
| 手动删除 | DELETE | 1 |

---

## 五、每天 AI 调用次数

| 场景 | 调 AI？ |
|------|:--:|
| 第一次分析（选英文） | ✅ 1 次（翻译+判词） |
| 回看历史（英文） | ❌ 0 次 |
| 切越南文 | ✅ 1 次（只此一次，翻完就缓存） |
| 再切回英文 | ❌ 0 次（display_i18n 里已经有了） |
| 同一商品再次分析 | ❌ 0 次（raw_json 在 DB） |

**每种语言一辈子只调一次 AI。**

## 六、表结构变更

```sql
ALTER TABLE analysis ADD COLUMN raw_json MEDIUMTEXT 
  COMMENT 'Apify 原始返回 JSON';
ALTER TABLE analysis ADD COLUMN favorited TINYINT(1) DEFAULT 0 
  COMMENT '收藏状态 0=未收藏 1=收藏（收藏后不参与 FIFO 自动清理）';
```

## 七、DB 清理逻辑

```sql
-- 分析完成时，超限清理（跳过收藏）
DELETE FROM analysis 
WHERE user_id=? AND favorited=0 
ORDER BY created_at ASC 
LIMIT {count - MAX};
-- MAX: free=20, paid=100，从 config 读
```
