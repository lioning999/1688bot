## 背景：判词系统设计结论

经讨论确定的最终架构——**程序定档，AI 写文字**。三者职责清晰，不可混：

| 层 | 职责 | 谁做 |
|---|---|---|
| 定档（tier + grade） | 判断商品/供应商好坏，给红绿灯 | 程序写死（规则引擎，纯函数） |
| 写判词文字 | 生成地道的产品/供应商/综合判词 | AI（Qwen），失败回退模板 |
| 染色（grade） | 前端显示 🟢🟡🔴⬜ | 前端，不进 AI |

### 「档」的三个层次（易混，务必分清）

| 层次 | 产品 | 供应商 | 综合 |
|---|---|---|---|
| **规则**（判断逻辑） | 12 条 | 6 条 | 矩阵查表 |
| **tier**（细分档，规则命中结果） | 12 个 | 5 个 | 9 个 |
| **grade**（粗档，前端红绿灯） | 4 档 go/ok/bad/none | 4 档 | headline 4 档 |

- grade 由 tier 映射而来，**写死在 mapping 表**，不是独立判断。
- grade 进 display JSON（`productEval.grade` / `supplierEval.grade`），前端染色。
- grade **不进 AI**；AI 拿的是 tier + tone + 数据 + 约束。

## 逐项说明

### 1. 删 4 个死 key

**位置**：`glossary.json` 中 `prod_verdict_go`、`prod_verdict_trial`、`prod_verdict_caution`、`prod_verdict_watch` 四条。

**原因**：旧版「4 档各写一句长判词」的残留。新版 4 档只需 `grade` 标签 + `prod_summary_*` 短摘要，不需要档位级长判词。代码已不引用。

**改法**：整条删除（含 zh/en/vi/th 全部语言）。

### 2. TODO 处理（B 方案）

**背景**：glossary 里约 40 条判词文案的 en/vi/th 是 "TODO"。降级链 `vi → en → zh` 会过滤 TODO，自动落到中文。

**方案 B（只补 en，vi/th 降级到 en）**：

| 列 | 动作 | 理由 |
|---|---|---|
| zh | 不动 | 已是中文原文 |
| en | 补 40 条英文 | en 是主力用户，AI 挂时必须有英文兜底 |
| vi / th | 删掉 TODO（留空） | 低频兜底，降级链落到 en（跨境电商英文通用） |

**涉及 key 范围**（以 glossary 实际 TODO 值为准，执行时 grep 确认）：
- `prod_verdict_*`（12 规则判词，约 11 条）
- `summary_*`（综合 9 档判词，约 9 条）
- `supp_verdict_*`（供应商判词，约 5 条）
- `supp_good_*` / `supp_bad_*` / `supp_action_*`（供应商好坏信号 + 动作）
- `prod_barrier_tip_*` / `prod_risk_note_no_return`（门槛附言 + 退货风险）

### 3. ai_verdict.py 三处 tier 精确匹配 bug（重要）

**根源**：恢复 12 规则后，tier 从简写 `"go"` 变回带后缀 `"go_repurchase"`，但 `ai_verdict.py` 里三处用 `p_tier == "go"` 精确匹配，全部匹配不上。共三处，同源：

#### 3a. `_derive_tone`（影响最大）

**现状**：
```python
if p_tier == "go":        # 实际 tier 是 "go_repurchase"，匹配不上
    return "positive"
if p_tier == "trial":     # 实际是 "trial_medium3"
    return "positive_but_cautious"
if p_tier == "caution":   # 实际是 "caution_hot_low"
    return "cautious"
```

**问题**：go/trial/caution 三类档的 tone 全部落成 `neutral`，AI 判词语气维度失效。

#### 3b. `_pack_product_must_not_say`（影响中等）

**现状**：`elif p_tier == "watch"`、`elif p_tier == "caution"` 匹配不上，watch/caution 档的禁说词（"strongly recommended"、"completely risk-free" 等）不生成。AI 可能说出禁词，且 `validate_ai_output` 因 must_not_say 缺失而放行。

#### 3c. `_pack_action`（影响低）

**现状**：`p_tier == "go"/"trial"/"caution"/"watch"` 匹配不上。因 supplier `action_key` 通常有值，此 fallback 少走；但 supplier skip 时会落到通用兜底文案。

**统一改法**：三处 `==` 全部改 `startswith`：
```python
# 3a
if p_tier.startswith("go"):
    return "positive"
if p_tier.startswith("trial"):
    return "positive_but_cautious"
if p_tier.startswith("caution"):
    return "cautious"
if p_tier.startswith("fatal"):
    return "negative"
return "neutral"

# 3b / 3c 同理：== "watch"/"caution"/"go"/"trial" → startswith(...)
```

### 4. 12 规则顺序重排

**位置**：`_product.py` 的 `_product_tier`。

**现状顺序**（caution 插在 trial 中间）：
```
trial_hot_unknown → caution_hot_low → trial_wanted_low → trial_rep_low/caution_rep_low → trial_medium3
```

**正确顺序**（trial 连续、caution 连续，与设计表一致）：
```
go_repurchase → go_hot_wanted → go_hot_repeat
→ trial_hot_unknown → trial_wanted_low → trial_rep_low → trial_medium3
→ caution_hot_low → caution_rep_low
→ watch_medium12 → watch_flat
```

**具体改动**：
- `caution_hot_low`（当前 Rule 7）从 trial 区挪到 `trial_medium3` 之后
- `trial_rep_low` / `caution_rep_low` 拆成两条独立规则，`trial_rep_low` 归 trial 区、`caution_rep_low` 归 caution 区

**影响**：边界 case 档位判定，非致命，但对齐代码与设计表。

### 5. docstring 对齐

**位置 1**：`evaluator.py` 顶部 docstring（第 10-11 行）：
```
_product.py   — 产品 6 维 → 致命检查 → 销量×门槛/退货 → 4 档 → 判词   ← 应改
_supplier.py  — 供应商 3 维 → 黑箱检查 → 信号强度计数 → 5 档 → 判词    ← 应改
```

**位置 2**：`_supplier.py` 第 1 行 docstring："…信号强度计数 → 5 档 → 判词"。

**改法**：统一为「12 规则 → 4 档 grade」「6 规则 → 4 档 grade」的准确描述，消除「产品 4 档 / 供应商 5 档」的误导。
