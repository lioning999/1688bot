## §3 存储策略

### 未登录用户

**没有保存按钮，数据纯内存。**

| 缓存 | 存什么 | TTL | 上限 | 位置 |
|------|--------|-----|------|------|
| `analysis_cache` | mapped（32 字段） | 30min | 500 条 | `domain/cache.py` |
| `display_cache` | display JSON（翻译后，按 `offerId:lang`） | 30min | 500 条 | `services/analyze_svc.py` |

服务重启 → 全部清空。不写 DB（无 user_id）。

### 登录用户点保存

**DB 存两列。**

| DB 列 | 存什么 | 为什么 |
|--------|--------|--------|
| `result_json` | mapped（32 字段，清洗+判词后） | **地基。** display 崩了从这重建，1ms。Apify 重抓 30s 还花钱。 |
| `display_i18n` | 翻译后的 display，按语言打包：`{"en":{...},"vi":{...},"th":{...},"id":{...}}` | 保存时从内存缓存一并写入，下次打开当前语言直接渲染，0 等待。懒加载补其他语言。 |

**不存翻译前 display。** 因为翻译前 display = `build_display(mapped)`，纯计算，1ms。mapped 在 DB，随时能重算。

**不存 Apify 原始 21 字段。** mapped 已是原始数据的超集（原始 21 → 计算后 32），信息不丢失。多存一份纯浪费磁盘。

**懒加载：不预翻译。** 用户请求某语言时才翻译该语言，写入 display_i18n。不主动翻 4 语言——浪费 Qwen 调用。

### 加载降级链

```
用户请求 offerId=xxx, lang=vi:

① display_i18n.vi 存在
   → 直接取 display_i18n JSON 的 vi 键 → 渲染（0 等待）

② display_i18n.vi 不存在
   → 取 result_json(mapped) → build_display(中文) → Qwen 翻译 vi → 渲染
   → 翻译结果写入 display_i18n.vi → UPDATE DB

③ result_json 不存在
   → 调 Apify 重抓 → mapper → verdict → build_display → 翻译 → 渲染

④ Apify 也失败
   → 返回错误给前端
```

**翻译源语言永远是中文原文。** 不存在"从已翻译的 vi 还原中文再翻成 th"这条路。

## §4 铁律（8 条）

| # | 铁律 | 防止什么问题 |
|---|------|-------------|
| 1 | **不猜测 Apify 字段名。** 新增字段必须用真实 Apify 返回数据验证，确认字段存在且类型正确后才写入 mapper。 | 上次 mapper 8 处 `or` 链瞎猜字段名 |
| 2 | **不保留死字段。** 新增/删除 mapped key 前，grep 全项目确认消费者：display_builder、translator 白名单、report.js renderV2。 | 上次 9 个死字段没人读，占着茅坑 |
| 3 | **改 key 前先 grep。** 改任何 mapped/display key 名，grep 全项目（`.py` `.js` `.json`），同步改完跑 72 测试。 | 上次改完 mapper 和前端对不上，静默空值 |
| 4 | **新增 display 文本字段必须同步 translator 白名单 + 映射表。** display 里加了中文字段 → 必须在 `translator.py` 的 `_TRANSLATABLE_SCALAR`（或 `_TRANSLATABLE_LIST`）+ `_KEY_IN_SOURCE` 映射表里加对应条目。翻译时有自动检查，含中文但不在白名单的字段会打 warning 日志。 | 上次加了字段前端看到中文，翻译漏了。`_KEY_IN_SOURCE` 不全靠命名巧合对上 |
| 5 | **翻译源 = 中文原文。** 任何语言的翻译必须从中文 display（Path 3 原文）翻过去。禁止从已翻译文本二次翻译。 | 防止 vi→中→en 翻译质量指数级衰减 |
| 6 | **display 新增顶层 key 必须同步测试。** 改了 `build_display` 的 return dict → 同步更新 `test_builds_all_top_level_keys` 的 `expected_keys`。 | 上次加 videoUrl 删 image，测试挂了才想起来 |
| 7 | **删东西前 grep 零引用。** 删函数/类/变量/常量前，grep 全项目确认无调用方。确认零引用再删。 | 上次 `_raw_card_value` `_factory_tag_value` 没人调还留着 |
| 8 | **前端唯一数据源 = display。** `renderResult` 所有数据从 `data.display` 取，禁止直读 `data.priceCNY` / `data.moq` / `data.unit` / `data.offerId` 等 mapped 顶层字段。display 里没有才加 display key，不走 mapped 旁路。 | 上次 4 个字段绕过 display 直读 mapped，display 契约被架空 |
