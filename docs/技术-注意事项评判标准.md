## 一、定位

| | 维度一（货品） | 维度二（供应商） | 维度三（注意事项） |
|:--|:--|:--|:--|
| 回答 | 这货能赚钱吗？ | 这供应商靠谱吗？ | 还有什么我没注意到的？ |
| 显示 | 始终显示 | 始终显示 | **条件触发，常态不显示** |
| 输出 | 标签 + 数据 + 人话 | 等级 + 标签 + 人话 | 0~3 条提醒 |

**核心原则：**
- 维度一二已经说过的 → 不重复
- 每条必须带**可执行动作**，不只描述问题
- 标题：`⚠️ 注意事项`

## 二、输入字段

| 字段 | 来源 | 类型 | 说明 |
|:--|:--|:--|:--|
| `product_score` | `product_evaluator.evaluate_product()` → `score` | int | 货品总分 0-12 |
| `supplier_score` | `supplier_evaluator.evaluate_supplier()` → `score` | int | 供应商总分 0-9 |
| `d1_identity` | `supplier_evaluator.evaluate_supplier()` → D1 score | int | 供应商身份分 0/1/2/3 |
| `price` | Apify `offer.price` | float | 单价（元） |
| `moq` | Apify `offer.moq` | int | 最小起订量 |

## 三、三种触发条件

### N1 — 维度间信号矛盾或双低

**触发条件（满足任一即触发）：**

| 子类型 | 条件 | 含义 |
|:--|:--|:--|
| 矛盾-货好供应商差 | `product_score >= 7 AND supplier_score <= 3` | 货品说"买"，供应商说"别买" |
| 矛盾-供应商好货差 | `product_score <= 3 AND supplier_score >= 7` | 供应商说"靠谱"，货品说"数据差" |
| 双低 | `product_score <= 3 AND supplier_score <= 3`（非双缺） | 两个维度都不理想 |
| 双缺 | `product_score == 0 AND supplier_score == 0` | 完全无法评估 |

**不触发：** 信号一致时（双高、双中、高中搭配），用户不需要额外提醒。

**理由：** 用户不是专业采购，面对矛盾信号不知道权重如何分配。注意事项帮他翻译成行动建议。

---

### N2 — 试错成本高

**触发条件：**

```python
price is not None and moq is not None and (price * moq) >= 500
```

**阈值依据：** ¥500 是心理门槛——超过这个数，拿样变成压货。低于 ¥500 不值得专门提醒。

**理由：** 维度一说"市场验证"，不说"你要花多少钱"。用户可能看到"月销 8900"就冲动下单，忽略了 MOQ 500 件的实际成本。

---

### N3 — 贸易商

**触发条件：**

```python
d1_identity == 1  # 贸易商，包括"非生产厂家"和普通商家
```

**不触发：** 认证工厂（D1=3）、普通工厂（D1=2）。

**理由：** 贸易商不是骗子，但加了一层差价。这是结构性成本，维度二评分评的是"可不可信"，评不出"你是不是多花了一层钱"。

## 四、合并与去重规则

### 独立性

N1、N2、N3 分别独立判断，可同时触发。上限 3 条。

### 去重

| 同时触发 | 处理 |
|:--|:--|
| N1（矛盾型）+ N3 | 各自独立，保留两条 |
| N1（双低型）+ N3 | **合并为一条**：双低已说明"两个维度都不好"，加一句"且为贸易商拿货"即可，不做两条 |
| N1（双缺型）+ N3 | 各自独立，保留两条（数据缺失和贸易商是两个不同信号） |

### 显示顺序

```
N1（如有）→ N2（如有）→ N3（如有）
```

| `caution_n1_good_bad` | 矛盾-货好供应商差 | 货品数据优秀，但供应商资质偏弱。好货配好供应商才靠谱，可找同类认证工厂拿样对比。 |

## 六、伪代码

```python
def build_cautions(product_score, supplier_score, d1_identity, price, moq):
    """返回 list[dict] — 0~3 条注意事项。每条 {key, params}。"""
    cautions = []

    # ---- N1: 信号矛盾/双低 ----
    is_double_zero = (product_score == 0 and supplier_score == 0)

    if is_double_zero:
        cautions.append({"key": "caution_n1_no_data", "params": {}})
    elif product_score >= 7 and supplier_score <= 3:
        cautions.append({"key": "caution_n1_good_bad", "params": {}})
    elif product_score <= 3 and supplier_score >= 7:
        cautions.append({"key": "caution_n1_bad_good", "params": {}})
    elif product_score <= 3 and supplier_score <= 3:
        # 双低 → 后面和 N3 合并判断
        cautions.append({"key": "caution_n1_double_low", "params": {}})

    # ---- N2: 试错成本 ----
    if price is not None and moq is not None and (price * moq) >= 500:
        cost_cny = int(price * moq)
        cost_usd = int(cost_cny / 7.2)
        cautions.append({
            "key": "caution_n2_high_cost",
            "params": {"cost_cny": cost_cny, "cost_usd": cost_usd}
        })

    # ---- N3: 贸易商 ----
    if d1_identity == 1:
        # 和 N1 双低去重
        is_double_low = (product_score <= 3 and supplier_score <= 3
                         and not (product_score == 0 and supplier_score == 0))
        if is_double_low:
            # 替换 N1 双低为合并版
            for i, c in enumerate(cautions):
                if c["key"] == "caution_n1_double_low":
                    cautions[i] = {"key": "caution_n1_double_low_trader", "params": {}}
                    break
        else:
            cautions.append({"key": "caution_n3_trader", "params": {}})

    return cautions  # 0~3 条
```

# 收尾行：总体建议 — 评判标准

> 必显示，一行斜体。放在 ② 块最末尾（维度一 → 维度二 → 注意事项 → **收尾行**）。

## 十一、定位

| | 维度一（货品） | 维度二（供应商） | 注意事项 | 收尾行 |
|:--|:--|:--|:--|:--|
| 回答 | 这货能赚钱吗？ | 这供应商靠谱吗？ | 还有什么我没注意到的？ | **所以，我下一步做什么？** |
| 显示 | 始终显示 | 始终显示 | 条件触发 | **始终显示** |
| 输出 | 标签+数据+人话 | 等级+标签+人话 | 0~3 条提醒 | **1 行斜体** |
| 性质 | 事实性评价 | 事实性评价 | 局部风险修正 | **全局行动建议** |

**核心原则：**
- **流程性建议，不是判断性建议。** 永远指向"拿样"这个动作，不说"建议购买"或"不建议购买"
- **每条带"因为"。** 不是"值得拿样"，而是"因为 A+B，所以值得拿样"
- **措辞比维度一二更保守。** 不替用户做决策，帮用户理清思路
- **不和注意事项打架。** 注意事项说"有个坑"，收尾行说"考虑完所有因素后的下一步"

## 十三、四档分档

| 档位 | 条件（Python） | 含义 | 出现率估计 |
|:--|:--|:--|:--|
| 🟢 推荐行动 | `product_score >= 7 and supplier_score >= 7` | 货验证充分 + 供应商靠谱，可以行动 | ~30% |
| 🟡 可以行动 | 其余组合（不满足🟢🔴⬜的所有情况） | 有亮点有不足，拿样补盲区 | ~60% |
| 🔴 谨慎行动 | `product_score <= 3 and supplier_score <= 3`（非双缺） | 两个维度都不理想 | ~8% |
| ⬜ 无法判断 | `product_score == 0 and supplier_score == 0` | 完全无法评估 | ~2% |

**判定顺序：** 先判⬜（双缺）→ 再判🔴（双低）→ 再判🟢（双高）→ 其余归🟡。

## 十五、伪代码

```python
def build_summary(product_score: int, supplier_score: int) -> dict[str, str]:
    """返回 {"key": str} — 收尾行 glossary KEY。必返回，无不显示情况。"""

    if product_score == 0 and supplier_score == 0:
        return {"key": "summary_no_data"}

    if product_score <= 3 and supplier_score <= 3:
        return {"key": "summary_careful"}

    if product_score >= 7 and supplier_score >= 7:
        return {"key": "summary_go"}

    return {"key": "summary_ok"}
```

**复杂度：** 4 个 if，零外部依赖，零参数。
