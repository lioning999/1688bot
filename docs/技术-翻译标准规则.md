# 翻译标准规则

> 新增/修改任何用户可见文字前，先走 §一 决策树确定归属，再改对应文件。
> 生命周期：活跃 | 更新：2026-07-28

---

## 一、决策树

```
这个字段最终会显示在用户屏幕上吗？
│
├─ NO → 不管（日志、异常名、变量名不在此规则范围）
│
└─ YES → 纯数字/URL/图片地址？
    │
    ├─ YES → ➖ 不翻译
    │
    └─ NO → 每种商品显示的文字完全一样吗？
        │
        ├─ YES → 🖥️ 前端 i18n
        │   文件：src/web/lang/i18n/{en,vi,th,id}.json
        │   举例：Tab名称、按钮、服务说明、验货清单、表单标签、错误提示
        │
        └─ NO → 中文原文从哪来？
            │
            ├─ 来自 1688/Apify 返回的数据
            │   → 🤖 Qwen 翻译
            │   文件：无固定配置。标题/规格/SKU名/公司名/地址/认证名/排名文字
            │   不能改原文，只能调 translator_prompts.json 提高翻译质量
            │
            └─ 来自我们写的逻辑/模板
                → 📖 字典查表
                文件：src/api/domain/term_glossary.json（术语唯一数据源，~101条 × 4语言）
                举例：判词、解释、sellerLabel、badge标签、单位、星级、格式化模板、产业带
                规则：中文KEY → 4语言翻译，不走Qwen。变量用{n}占位，前端填入数字。
```

---

## 二、三层归属

| 层 | 判断标准 | 翻译方式 | 文件 |
|----|---------|---------|------|
| 🖥️ 前端i18n | 每种商品一样 | JS 运行时替换 | `src/web/lang/i18n/{lang}.json` |
| 📖 字典查表 | 中文由我们产出，可穷举 | 直接查表，不走 Qwen | `term_glossary.json` |
| 🤖 Qwen翻译 | 中文来自 1688，不可穷举 | Qwen 运行时翻译 | translator.py，无固定配置 |
| ➖ 不翻译 | 数字/URL/图片 | 无 | 无 |

---

## 三、各层详解

### 🖥️ 前端 i18n

**放什么：** 页面壳。每种商品完全一样的静态 UI 文案。

```
✅ Tab名称: "产品" / "Product"
✅ 按钮: "分析" / "Analyze"
✅ 服务说明: "✅ 1688下单 · 收货 · 验货..."
✅ 验货清单: "颜色是否与商品图一致"
✅ 表单标签: "数量" / "国内运费"
✅ 错误提示: "网络错误，请检查网络后重试"
✅ 占位符: "粘贴 1688 商品链接..."
✅ 兜底文字: "No Certification"

❌ 商品标题 → 1688返回
❌ 判词 → 我们写的，每种商品不同
❌ 商家身份 → 我们写的，每种商品不同
```

**文件:** `src/web/lang/i18n/en.json`, `vi.json`, `th.json`, `id.json`

**改词操作:** 四个 JSON 文件找到对应 key 改值。不同步即不同步——每种语言独立维护。

---

### 📖 字典查表（term_glossary.json）

**放什么：** 中文原文由我们产出、且可能值有限的文字。

```
✅ 卖家身份: "源头工厂"/"贸易商" → 4语言
✅ Badge标签: "免费拿样"/"买家保障"/"跨境专供"/"包邮"/"7天退货"/"支持混批"等 → 4语言
✅ 单位映射: "个"→"pcs"/"套"→"set"/"包"→"pack"/... → 4语言
✅ 星级: ★★★Recommended / ★★☆Consider / ★☆☆Limited Data → 4语言
✅ 格式化模板: "{n}+ sold" / "{n}y on 1688" / "{n}% repurchase" → 4语言
✅ 判词: 产品/工厂/拿样各分支 → 4语言（待迁入）
✅ 解释文案: sales/factory各分支 → 4语言（待迁入）
✅ emoji前缀: "🏭 " / "🏆 " → 4语言

❌ 商品标题 → 1688返回，无法穷举
❌ 规格参数值 → 1688返回
❌ 公司名称 → 1688返回
```

**文件:** `src/api/domain/term_glossary.json`

**结构:**
```json
{
  "源头工厂": {
    "en": "Factory",
    "vi": "Nhà Máy",
    "th": "โรงงาน",
    "id": "Pabrik"
  },
  "sold_format": {
    "en": "{n} sold",
    "vi": "Đã bán {n}",
    "th": "ขายแล้ว {n}",
    "id": "{n} terjual"
  }
}
```

**改词操作:** 
- 改翻译 → 改对应语言的值
- 改中文原文 → 改 KEY 名 + 所有代码引用处
- 新增 → mapper/display_builder 加产出 + glossary 加翻译

### 🤖 Qwen 翻译

**放什么：** 1688/Apify 返回的中文原始数据。我们无法控制原文，也不能穷举。

```
✅ 商品标题: raw.title
✅ 规格参数: raw.specs → mapper _filter_specs()
✅ SKU名称: raw.skuImages[].name
✅ 公司名称: raw.supplier.companyName
✅ 地址: raw.shipping.location
✅ 认证类型名: raw.supplier.certification.type
✅ 排名文字: raw.supplier.rank.text
✅ 工厂实力原文: mapper _build_factory_flags() 产出的中文标签组合

❌ 判词 → 我们写的，应走字典
❌ 解释文案 → 我们写的，应走字典
❌ sellerLabel → 穷举完了，应走字典
```

**改词操作:** 
- ❌ 不能改中文原文（1688 商家写什么就是什么）
- ✅ 调翻译质量 → 改 `translator_prompts.json`（system prompt / template / forbidden words）
- ✅ 术语一致性 → 改 `term_glossary.json`（Qwen翻译时会用术语表）

## 四、铁律

### 铁律一：禁止在代码中硬编码展示文案

Python/JS 代码中不得出现用户可见的固定文字。所有展示文字必须在 i18n JSON 或 term_glossary.json 中。

```python
# ❌ 违宪
f"{n}+ sold"
"7-Day Returns"
f'<span class="price-moq">· MOQ <strong>{moq}</strong></span>'
```

```python
# ✅ 正确
glossary[lang]["sold_format"].format(n=n)    # term_glossary.json
i18n("price.moqLabel")                        # 前端 i18n
```

**适用范围:** 用户屏幕上可见的任何字符串。不适用范围：日志、异常名、变量名。

### 铁律二：新增展示字段前先确定归属层

每新增一个用户可见字段，必须在 PR 中注明属于决策树的哪一层。同类字段不在同一层 → 驳回。

### 铁律三：术语单一数据源

`term_glossary.json` 是术语翻译的唯一来源。Qwen 翻译用的术语表由 `translator.py` 从 `term_glossary.json` 动态生成，不得在 `translator_prompts.json` 中重复定义术语。

### 铁律四：改中文原文必须同步检查4语言翻译

修改 `term_glossary.json` 中任一中文 KEY 对应的翻译文案时，必须同步检查 en/vi/th/id 四语言是否对应。若不打算同步 → 删除旧翻译值，前端降级显示中文。不得保留过时翻译。

> 此铁律已纳入根 `CLAUDE.md` §九。

## 五、反面示例

### 反例1：在 Python 里拼英文展示文案

```python
# ❌ display_builder.py
f"{_fmt_num(sold)}+ sold"
f"{years}y on 1688"
"7-Day Returns"
```

### 反例2：在 JS 里硬编码壳文字

```js
// ❌ report.js
'<span>· MOQ <strong>' + moq + '</strong></span>'
'1688 →'
'No Certification'
```

### 反例3：我们的模板走 Qwen 翻译

```
❌  判词中文模板 → Qwen 翻译（每次运行时翻译同样的句子，浪费 API）
✅  判词中文模板 → 4语言字典（预翻译好，0 API 调用）
```

### 反例4：术语两处定义不一致

```json
// ❌ term_glossary.json
"源头工厂": {"en": "Factory"}
// ❌ translator_prompts.json glossary
"源头工厂 → Source Factory"   // 同一个词，两处翻译不一样
```
