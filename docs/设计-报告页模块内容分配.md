## 一、5 模块总览

```
① 商品确认  →  "是不是我搜的那款？"
② 综合结论  →  "值不值得拿样？"（3 行，3 秒看完）
③ 分项论据  →  "凭什么下这个结论？"（4 组，想验证就往下翻）
④ 拿样发货  →  "怎么试？什么保障？"
⑤ 行动按钮  →  "好，行动。"
```

---

## 二、②③ 内容边界

| | ② 综合结论 | ③ 分项论据 |
|:--|:--|:--|
| 作用 | **3 秒做决定** | **验证为什么** |
| 内容量 | 3 行 | 4 组 × 若干维度 |
| 用户行为 | 看完决定"继续"或"跳过" | 决定"继续"后，往下翻看细节 |

### ② 放什么（3 行）

| 行 | 内容 | 来源 | 字体 |
|:--|:--|:--|:--|
| 1 | 收尾行 | `build_summary()` | **大字** |
| 2 | 注意事项（如有，≤2条） | `build_cautions()` | 小字，黄色背景 |
| 3 | 一行摘要 | product_score + supplier_grade | 小字，灰色 |

**示例：**
```
🟢 值得拿样。货品验证充分 + 供应商靠谱。
⚠️ 贸易商拿货，可对比工厂价格。
📦货品12分 · 🏭⚠️可合作
```

### ③ 放什么（4 组）

所有 evaluator 输出的细节——标签、数据、人话、等级——全部进 ③。

---

## 三、③ 分项论据：4 组完整内容

### 分组原则

**按用户决策顺序，不是按指标类型：**

```
📦 货品验证   →  这货能卖吗？
🏭 供应商资质 →  谁在卖？靠谱吗？
⚠️ 风险提示   →  有什么坑？
💰 利润空间   →  能赚多少？
```

---

### 📦 货品验证（6 个维度 + 组尾总结）

**用户看完知道：** 这货市场验证过了吗？

| # | 维度 | 来自 | 展示内容 | 理由 |
|:--|:--|:--|:--|:--|
| 1 | 销量 | `product_evaluator` D1 | 标签（🔥热销品）+ 档位（🟢/🟡/🔴）+ 数据（月销8900+） | 卖得好不好→这货有没有市场 |
| 2 | 复购 | `product_evaluator` D2 | 标签（🔄高复购）+ 档位 + 数据（复购67.5%） | 买了还买→质量好不好 |
| 3 | 口碑 | `product_evaluator` D4 | 标签（⭐口碑好）+ 档位 + 数据（好评99.6%） | 收货人满意→不会翻车 |
| 4 | 门槛 | `product_evaluator` D3 | 标签（💰低门槛）+ 档位 + 数据（¥2/件·起订2件） | 试错便不便宜→放心试 |
| 5 | 排名 | Apify `supplier.rank.text` | 原始文本（🏆 防护眼镜热销榜TOP3） | 1688 排行=官方认证的爆款 |
| 6 | 库存 | Apify `stock` | 数字（库存7100万件） | 不会断货→爆单有底气 |

**组尾总结：** `product_evaluator` 人话行（"市场反复验证，数据全面优秀，试错成本低，值得拿样"）

**组标题格式：** `📦 货品验证 · 12/12分`

---

### 🏭 供应商资质（4 个维度 + 组尾总结）

**用户看完知道：** 谁在卖？靠谱吗？

| # | 维度 | 来自 | 展示内容 | 理由 |
|:--|:--|:--|:--|:--|
| 1 | 身份 | `supplier_evaluator` D1 | 标签（🏭认证工厂/🏭工厂直供/⚠️贸易商）+ 档位（🟢/🟡/🔴） | 是不是源头→你多不多花一层钱 |
| 2 | 平台认证 | `supplier_evaluator` D1 的 flags | 平台标签（实力商家/超级工厂/源头旗舰等） | 1688 官方给的背书 |
| 3 | 品质认证 | `supplier_evaluator` D2 | 标签（📋深度验厂）+ 认证详情（TUV/编号/报告链接） | 第三方验过→品质有保障 |
| 4 | 年限 | `supplier_evaluator` D3 | 标签（📅老店/📅新店）+ 年数 | 干得久→不是今天开明天跑 |

**组尾总结：** `supplier_evaluator` 人话行（"贸易商非源头工厂，但4年老店+深度验厂认证信誉可查..."）

**组标题格式：** `🏭 供应商资质 · ⚠️可合作 · 7/9分`

---

### ⚠️ 风险提示（0~3 条，条件显示）

**用户看完知道：** 有什么坑？为什么重要？怎么办？

| # | 触发条件 | 来自 | 展示内容 | 理由 |
|:--|:--|:--|:--|:--|
| N1 | 信号矛盾或双低 | `caution_builder` | 风险描述 + 为什么 + 替代方案 | 货和人不匹配→最容易忽略的坑 |
| N2 | price×MOQ ≥ ¥500 | `caution_builder` | 试错金额 + 为什么 + 建议 | 钱的问题→最直观的坑 |
| N3 | 贸易商 | `caution_builder` | 身份说明 + 为什么 + 替代方案 | 结构性成本→评分看不出来 |

**和 ② 块注意事项的区别：**

| | ② 注意事项 | ③ 风险提示 |
|:--|:--|:--|
| 内容 | 一句话结论 + 行动建议 | 风险描述 + 为什么 + 详细建议 |
| 条数 | 精简版，≤ 2 条 | 完整版，不限制 |
| 示例 | "⚠️贸易商拿货，可对比工厂价" | "为什么贸易商是风险：你不是从源头拿货，中间多一层差价。替代方案：搜索同类工厂直供商品对比价格。" |

**当 N1/N2/N3 全都不触发时，③ 的 ⚠️ 组不渲染。**

---

### 💰 利润空间（1 个维度，旧逻辑不变）

**用户看完知道：** 能赚多少？

| 内容 | 说明 |
|:--|:--|
| 阶梯价 | 2件 ¥2/件，100件 ¥1.8/件（来自 Apify） |
| 用户填售价 | 预估在当地卖多少钱（用户输入） |
| 用户填运费 | 预估国际运费（用户输入） |
| 利润结果 | 毛利率 XX%，单件利润 ¥XX |

**理由：** 利润计算涉及用户自己的售价和运费，不是 1688 数据。旧逻辑不变，独立成组。

## 四、数据流：evaluator → 模块

```
evaluator 输出              分配目标
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

product_evaluator
  ├─ labels (4个)       →  ③ 📦 货品验证（每标签一行）
  ├─ data (数字)        →  ③ 📦 货品验证（每数字一行）
  ├─ human (人话)       →  ③ 📦 货品验证（组尾总结）
  └─ score (0-12)       →  ② 一行摘要 + ③ 📦 组标题

supplier_evaluator
  ├─ grade (✅⚠️🔴)     →  ② 一行摘要 + ③ 🏭 组标题
  ├─ labels (3个)       →  ③ 🏭 供应商资质（每标签一行）
  ├─ flags (平台标签)   →  ③ 🏭 供应商资质 > 平台认证
  ├─ human (人话)       →  ③ 🏭 供应商资质（组尾总结）
  └─ score (0-9)        →  ② 一行摘要 + ③ 🏭 组标题

caution_builder
  ├─ N1 (矛盾/双低)     →  ② 精简版 + ③ ⚠️ 完整版
  ├─ N2 (试错成本)      →  ② 精简版 + ③ ⚠️ 完整版
  └─ N3 (贸易商)        →  ② 精简版 + ③ ⚠️ 完整版

build_summary
  └─ 收尾行             →  ② 大字结论（不进入 ③）

rank.text               →  ③ 📦 货品验证 > 排名
stock                   →  ③ 📦 货品验证 > 库存
Apify 价格/阶梯价       →  ③ 💰 利润空间
```

## 五、前端渲染规则

| 模块 | 规则 |
|:--|:--|
| ② 综合结论 | 始终渲染，3 行。注意事项为空时不渲染该行 |
| ③ 📦 货品验证 | 始终渲染。组标题带分数。无数据维度显示"数据不足" |
| ③ 🏭 供应商资质 | 始终渲染。组标题带等级+分数 |
| ③ ⚠️ 风险提示 | **条件渲染。** `cautions` 数组为空时，整个组不渲染 |
| ③ 💰 利润空间 | 始终渲染 |
| ③ 各组排序 | 📦 → 🏭 → ⚠️ → 💰（固定顺序） |
| ③ 组内折叠 | V1 不折叠。V1.1 根据用户反馈决定是否加折叠 |

---

## 六、改动影响

| 模块 | 改动量 | 说明 |
|:--|:--|:--|
| ② 综合结论 | 轻 | 只展示 3 行，删掉 demo 里的标签/数据/人话详情 |
| ③ 分项论据 | 重 | 新建 4 组结构，接住所有 evaluator 输出 |
| ④ 拿样发货 | 无 | 不变 |
| ⑤ 行动按钮 | 无 | 不变 |

---

## 七、确定性保证

同一组 Apify 原始数据 → 同一组 evaluator 输出 → 同一组 ②③ 分配。**零随机，100% 确定性。**
