# 错误监控方案

> 目录索引：[[docs/README.md]] · [[docs/项目架构宪法.md]]
> 生命周期：**草案** · 创建：2026-07-25

---

## 目标

后端代码报错时 → 自动通知到监控后台，知道哪里崩了、什么时候崩的、影响了谁。

V1 当前状态：错误只打印到本地日志，没人看。用户报错你完全不知道。

---

## 方案对比

| | Sentry 免费版 | GlitchTip 自部署 |
|------|------|------|
| 月免费额度 | 5,000 错误事件 | 无限制（自己的服务器） |
| 部署 | SaaS，注册即用 | 需要 Docker 部署 |
| 功能 | 完整的错误聚合/堆栈/面包屑/告警 | 和 Sentry 兼容的 API，功能精简 |
| V1 费用 | $0 | 服务器资源（已有服务器可复用） |
| 维护成本 | 零 | 需自己升级/维护 |
| **推荐** | ✅ V1 用这个 | V2 考虑 |

**结论：V1 直接用 Sentry 免费版。** 每月 5,000 个错误事件，日均 166 个，V1 一天可能几个错误，完全够。

## Sentry 接入步骤

### 1. 安装 SDK

```bash
pip install sentry-sdk
```

### 2. main.py 初始化（加 3 行）

```python
import sentry_sdk

sentry_sdk.init(
    dsn=os.getenv("SENTRY_DSN", ""),
    environment=os.getenv("ENV", "production"),  # production / staging
    traces_sample_rate=0.1,  # 10% 请求记录性能追踪
)
```

加在 `app = FastAPI()` 之后、中间件之前。

### 3. .env 加配置

```bash
SENTRY_DSN=https://xxx@xxx.ingest.sentry.io/xxx
```

### 4. 注册 Sentry 账号

1. 打开 [sentry.io](https://sentry.io) → Sign up with Google
2. Create Project → Python → FastAPI
3. 复制 DSN → 填到 `.env`

## 监控什么

初始化后，以下内容自动上报，**不需要额外写代码**：

| 自动捕获 | 说明 |
|------|------|
| 未处理的异常 | 任何 `raise` 出去的异常自动上报 |
| HTTP 500 错误 | FastAPI 中间件自动捕获 |
| 请求上下文 | URL、method、query params、user agent |
| 堆栈信息 | 哪一行报的错、调用链 |

### 手动上报（特定场景）

```python
import sentry_sdk

# 上报一个不是异常、但你需要知道的事件
sentry_sdk.capture_message("Apify 今日配额用尽")

# 给异常加更多上下文
with sentry_sdk.push_scope() as scope:
    scope.set_tag("offer_id", offer_id)
    scope.set_user({"id": user_id})
    sentry_sdk.capture_exception(e)
```

## 告警配置

在 Sentry 网页后台配置：

| 告警 | 条件 |
|------|------|
| 新错误出现 | 任何时候 |
| 错误频率突增 | 1 小时内同一错误 > 10 次 |
| 连续错误 | 5 分钟内持续报错 |

通知方式：Email（免费版支持），Slack/WhatsApp（需升级）

---

## 不监控什么

| 不监控 | 原因 |
|------|------|
| 前端 JS 错误 | V1 先看后端，前端错误用户自己会反馈 |
| 性能慢请求 | V1 用户量小，不是瓶颈 |
| 用户行为链路 | 需要前端 SDK，V2 再加 |

## 降级策略

如果 Sentry 挂了（极端情况），不影响网站正常运行：

```python
# sentry_sdk.init() 失败时自动降级为 silent mode
# 错误仍然会打印到本地日志
# 网站正常响应用户请求
```

## 注意

1. **DSN 是敏感信息** — 不要提交到 git。已在 `.env` 中，`.env` 已在 `.gitignore`。
2. **生产环境不要开 `debug=True`** — 会导致 Sentry 不上报（Sentry 默认忽略 debug 模式）。
3. **GlitchTip 兼容 Sentry SDK** — 如果以后想自部署，把 DSN 换成 GlitchTip 的地址就行，代码不用改。
