## 一、背景

现有 `report.html` 采用 3-Tab 布局（产品/工厂/拿样）。新版改为 5 模块单页滚动布局：

```
① 商品确认  →  "是不是我搜的那款？"
② 综合结论  →  "值不值得拿样？"（3 行，3 秒看完）
③ 分项论据  →  "凭什么下这个结论？"（4 组：📦货品·🏭供应商·⚠️风险·💰利润）
④ 拿样发货  →  "怎么试？什么保障？"
⑤ 行动按钮  →  "好，行动。"
```

**核心决策：不动 report.html，新建 `inspect.html`。** 两页共存，旧页保留给已收藏链接的用户缓冲。

## 二、架构原则

| 原则 | 说明 |
|:--|:--|
| 纯增量 | 旧文件不动，新字段追加到 display JSON，新文件独立建 |
| 复用翻译管线 | 新 evaluator 全部走 glossary 查表（📖字典层），不动 i18n/Qwen |
| 复用 API 管线 | 同一套 Apify→mapper→display 流程，inspect.html 只是不同的 display JSON 消费者 |
| 一个领域一个文件 | 4 个新 evaluator 函数放一个 `evaluator.py`，不拆成 4 个文件 |
| 旧 verdict_engine 不动 | `judge_product/judge_factory/judge_sample` 保留，给旧 report.html 用 |

## 五、product_mapper 新增字段

在 `map_raw()` 返回 dict 中新增以下 key：

| 字段 | 类型 | 来源 | 清洗逻辑 |
|:--|:--|:--|:--|
| `cert_key` | str | `supplier.certification` 原始字符串 | CERT_MAP 查表归一化。未识别→`""` |
| `identity_key` | str | `supplier.flags` + `sellerType` | 归一化为 glossary KEY：`认证工厂`/`工厂直供`/`贸易商`/`信息不足` |
| `shop_years_clean` | int | `supplier.tpYear` | None→0, str→int, 负→0 |
| `has_cert` | bool | `cert_key != ""` | — |
| `has_years` | bool | `shop_years_clean > 0` | — |

**CERT_MAP（1688 原始值 → glossary KEY）：**

| 1688 原始值 | glossary KEY | 备注 |
|:--|:--|:--|
| `TUV Rheinland` / `TUV` | `深度验厂` | TUV 属于深度验厂的一种 |
| `SGS` | `SGS 实地认证` | 已有 |
| `深度验厂` | `深度验厂` | 已有 |
| `实地认证` | `实地认证` | 已有 |
| `第三方验厂` | `第三方验厂` | 已有 |
| 空 / None / `暂无认证` | `""` | 模板走缺数据分支 |

**identity 归一化规则：**

| 条件 | identity_key |
|:--|:--|
| flags 含 超级工厂/源头旗舰/实力工厂 | `认证工厂` |
| flags 含 isFactory 且不含 非生产厂家 | `工厂直供` |
| flags 含 非生产厂家 | `贸易商` |
| 无有效数据 | `信息不足` |

## 六、evaluator.py 规格

### 6.1 evaluate_product(mapped) → dict

**输入：** `product_mapper.map_raw()` 输出

**输出：**
```python
{
    "score": int,           # 0-12
    "labels": [str],        # 标签 KEY 列表，如 ["hot_product", "high_repurchase"]
    "data_rows": [          # 维度数据行
        {"label_key": "D1_label", "value": "月销8,900+", "tier": "🟢", "ref": "标杆 >1000"},
        ...
    ],
    "human": {              # 组尾人话，传给 _format_verdict()
        "key": "product_human_go",   # 按 score 四档选 key
        "params": {}
    }
}
```

**分档逻辑（四档选 human key）：**

| score | human key |
|:--|:--|
| 10-12 | `product_human_go` |
| 4-9 | `product_human_ok` |
| 1-3 | `product_human_careful` |
| 0 | `product_human_none` |

详细分档表（D1-D4 每维度 0-3 分规则）见 [技术-货品维度评判标准.md](技术-货品维度评判标准.md)。

---

### 6.2 evaluate_supplier(mapped) → dict

**输入：** `product_mapper.map_raw()` 输出（含新增清洗字段）

**输出：**
```python
{
    "score": int,           # 0-9
    "grade": str,           # "✅可信" / "⚠️可合作" / "🔴谨慎" / "⬜数据不足"（KEY）
    "labels": [str],        # 标签 KEY 列表
    "data_rows": [...],     # 维度数据行
    "human": {              # 组尾人话
        "key": "supplier_human_go_has_data",  # 四档 × 2 分支（有数据/缺数据）
        "params": {
            "identity": "认证工厂",   # glossary KEY
            "cert": "深度验厂",       # glossary KEY
            "years": "4"
        }
    }
}
```

**分支模板逻辑：**

每个档位 2 条模板（有数据 / 缺数据），共 8 条：

| 档位 | 有数据 KEY | 缺数据 KEY |
|:--|:--|:--|
| 🟢 7-9 | `supplier_human_go_data` | `supplier_human_go_none` |
| 🟡 4-6 | `supplier_human_ok_data` | `supplier_human_ok_none` |
| 🔴 1-3 | `supplier_human_bad_data` | `supplier_human_bad_none` |
| ⬜ 0 | — | `supplier_human_none` |

- **有数据：** `has_cert` 或 `has_years` 至少一个为 True
- **缺数据：** 两者都为 False
- ⬜ 档位只有缺数据版本

详细分档表（D1-D3 每维度 0-3 分规则）见 [技术-供应商维度评判标准.md](技术-供应商维度评判标准.md)。

---

### 6.3 build_cautions(p_score, s_score, identity_key, price, moq) → list

**返回：** `[{key, params}, ...]` 或 `[]`（无风险）

触发条件（N1/N2/N3）详见 [技术-注意事项评判标准.md](技术-注意事项评判标准.md)。

---

### 6.4 build_summary_line(p_score, s_score) → dict

**返回：** `{"key": "summary_go"}` — ② 收尾行 glossary KEY

| 条件 | key |
|:--|:--|
| p_score == 0 and s_score == 0 | `summary_none` |
| p_score <= 3 and s_score <= 3（非双缺） | `summary_careful` |
| p_score >= 7 and s_score >= 7 | `summary_go` |
| 其余 | `summary_ok` |

## 七、display JSON 变更

### 7.1 新增字段

```python
# _EXPECTED_KEYS 新增：
"productEval",     # dict — ③📦 货品评估（score + labels + data_rows + human）
"supplierEval",    # dict — ③🏭 供应商评估（score + grade + labels + data_rows + human）
"cautions",        # list — ③⚠️ 风险提示（每个元素为 _format_verdict 输出）
"summaryLine",     # str  — ② 收尾行（已翻译文本）
```

### 7.2 新增 _build_xxx() 函数

```python
def _build_product_eval(mapped, lang):
    result = evaluate_product(mapped)
    return {
        "score": result["score"],
        "labels": [_glossary(k, lang) for k in result["labels"]],
        "data_rows": result["data_rows"],
        "human": _format_verdict(result["human"], lang),
    }

def _build_supplier_eval(mapped, lang):
    result = evaluate_supplier(mapped)
    return {
        "score": result["score"],
        "grade": _glossary(result["grade"], lang),
        "labels": [_glossary(k, lang) for k in result["labels"]],
        "data_rows": result["data_rows"],
        "human": _format_verdict(result["human"], lang),
    }

def _build_cautions(mapped, lang):
    p = evaluate_product(mapped)
    s = evaluate_supplier(mapped)
    items = build_cautions(p["score"], s["score"], ...)
    return [_format_verdict(item, lang) for item in items]

def _build_summary_line(mapped, lang):
    p = evaluate_product(mapped)
    s = evaluate_supplier(mapped)
    result = build_summary_line(p["score"], s["score"])
    return _format_verdict(result, lang)
```

### 7.3 旧字段保留

```python
"verdictProduct": _format_verdict(mapped.get("verdict_product"), safe_lang),  # 不动
"verdictFactory": _format_verdict(mapped.get("verdict_factory"), safe_lang),  # 不动
"verdictSample":  _format_verdict(mapped.get("verdict_sample"),  safe_lang),  # 不动
```

|:--|:--|

## 九、前端渲染规则

### 9.1 inspect.html 加载顺序

```
lang-detect.js → i18n.js → api/core.js → components.js → inspect.js
```

与 report.html 相同。

### 9.2 inspect.js 渲染逻辑

```js
// 从 display JSON 读取
var ev = display.productEval;    // ③📦
var sv = display.supplierEval;   // ③🏭
var cautions = display.cautions; // ③⚠️
var summary = display.summaryLine; // ②

// ② 收尾行 — 始终渲染
// ③📦 — 始终渲染，组标题带分数
// ③🏭 — 始终渲染，组标题带等级+分数
// ③⚠️ — cautions.length === 0 时渲染 "✅ 未发现明显风险"
// ③💰 — 始终渲染（复用现有 profit 逻辑）
// ④⑤ — 始终渲染
```

### 9.3 模块条件渲染规则

| 模块 | 规则 |
|:--|:--|
| ② | 始终渲染。`summaryLine` 为 `""` 时不渲染该行 |
| ③📦 | 始终渲染 |
| ③🏭 | 始终渲染 |
| ③⚠️ | `cautions` 为空数组 → 渲染占位："✅ 未发现明显风险" |
| ③💰 | 始终渲染 |
| ④⑤ | 始终渲染 |

## 十三、确定性保证

同一组 Apify 原始数据 → 同一组 mapper 清洗字段 → 同一组 evaluator 输出 → 同一组 display JSON 字段 → 同一组 glossary 模板渲染。**零随机，100% 确定性。**
